# 赛场光照与外观（venue lighting）

`worlds/rmuc_2027_venue.sdf` 是 `rmuc_2027.sdf` 的另一个版本：几何不变，光照和表面外观按 RMUC 2026 总决赛（深圳，2026-08-05）的真实场地还原。原 world 和原模型都没有改。

```bash
./run_venue.sh                       # 第一次运行会先生成 *_lit 模型（约 1 秒）
python3 tools/build_venue_lighting.py  # 手动重新生成
```

## 方法

海康自瞄相机（MV-CS016-10UC，曝光 4000 µs，增益 8 dB，无 gamma）的内录在这里只当测量工具用。它的低曝光、灯条过曝、未知的白平衡都不带进场景。用到的是与曝光无关的量：

- **光从哪来、环境光多少**：竖直面与水平面、阴影与受光面的亮度比。
- **表面反射率**：同一帧、同一光照下两种表面的亮度比就是反照率之比。
- **LED 颜色**：灯条过曝的芯不能用，取芯边缘未过曝像素的色度。

视频、测量脚本和全部测量值在 [`../video/`](../video/README.md)，`tools/build_venue_lighting.py` 直接读取 `video/measurements.json`。

录像只能给出比例，所以需要一个绝对锚点：**白色地面漆反照率取 0.8**（常见白漆 0.75–0.85）。

Gazebo 相机没有曝光（像素 = 反照率 × 光照），绝对亮度按“自动曝光正常的相机”定：反照率 1 的水平面在全场平均光照下为线性 0.8。整体调亮调暗改 `E_WHITE`，所有比例不变。

## 实测与仿真

仿真值来自线性化后的渲染图（地面视角高 0.45 m，无人机视角高 1.5 m、水平视场 87°）。

| 量 | 实测（海康录像） | 仿真 |
|---|---|---|
| 地面 / 白标线 | 0.333（地面 15.5, 16, 12.5 DN，白标线 44, 46, 42 DN，同帧相邻） | 0.330–0.335 |
| 墙、高地侧面、中央结构 / 地面 | 0.04–0.08（0.6–1.3 DN 对 14–18 DN；坡道侧面 0.16） | 0.040–0.069 |
| 蓝色地面漆 / 地面（G） | 0.45, 0.65, 1.48（三段中位数） | 0.44, 0.62, 1.38 |
| 阴影 / 受光地面 | 0.05–0.14（14-42-34 底部 0.14） | 0.08 |
| 近竖直白面（仰 15°）/ 水平白面 | 0.24–0.35 | 0.25 |
| 观众席、天花板 | 0 DN | 黑 |
| LED 横幅 / 白标线 | (20, 16, 23) / 50 | 同比例 |
| 蓝 / 红 / 绿灯条色度 | (0.07, 0.41, 1) / (1, 0.41, 0.09) / (0.49, 1, 0.83) | 同值，满强度发光 |
| 灯条亮度 / 白标线 | ≥ 5.5（芯全部过曝） | 满强度（8 bit 相机的上限） |

## 场景里改了什么

| 项目 | 原 world / CAD | venue world | 依据 |
|---|---|---|---|
| 光源 | 1 个斜射方向光 | 12 个顶灯（spot，4 × 3，高 16 m，向下，开阴影），中性白 | 竖直/水平比、均匀度 |
| 环境光 | gz 默认 | 直射光的 8% | 阴影/受光比；gz 没有间接光，用环境光代替地面反射到阴影里的光 |
| 背景 | 灰 | 黑 | 观众席、天花板 0 DN |
| 地面、道路、高地顶面（CAD 灰 0.033 / 0.053，朝上为主且低于 1.1 m） | 0.033 / 0.053 | 0.266 | 地面/白标线 × 0.8 |
| 墙、高地侧面（CAD 米色）、中央结构和高墙（CAD 灰的其余部分） | 0.578（米色）/ 0.033 | 0.12，保留 CAD 色相 | 墙/地面比 |
| 白色漆 | 1.0 | 0.8 | 锚点 |
| 蓝色漆 | 0, 0, 1 等 | 0.120, 0.173, 0.394 | 蓝漆/地面比 |
| 红色漆 | 1, 0.002, 0.002 | 0.394, 0.173, 0.120 | 录像里看不到红漆，按蓝漆镜像推断（CAD 值的红色反射比白漆还高，不现实） |
| 灯条 | 不发光 | 发光，颜色为实测色度 | 灯条芯边缘像素 |
| 场馆 | 无 | 顶灯位置的发光圆盘，场地外一圈 LED 横幅 | 录像中可见 |

其余材质（能量机关、基地贴图、贴纸、小零件等）在录像里看不清，保持 CAD 颜色。生成脚本只改 glTF 的材质参数，几何数据逐字节相同。

## 实现细节

- gz-sim 8 / ogre2 的响应用标定 world 测过：spot 灯在距离 d 处给出线性亮度 0.665 × 反照率 × I / d²（二次衰减系数 1）；环境光 a 给出 0.32 × a × 反照率。相机输出是 sRGB 编码。
- 墙的反照率 0.12 是让渲染出的墙/地面比落在实测范围内的值。它比“纯粹按亮度比算”的 0.03–0.05 高，因为 Gazebo 里竖直墙面只受直射光，真实墙面还有地面反射过来的光。
- 灯条的识别：高饱和颜色、总面积 < 1 m²、水平面占比 < 0.5。同样颜色的大平面是地面漆。
- 灯具高度、数量和位置从视频里定不了，只满足上表的比例。6 × 4 开阴影时 ogre2 在地面上出现成块的阴影伪影，4 × 3 的亮度和均匀度相同、阴影正常。
- 光色用中性白：录像里白标线 R/G/B 比为 0.96 : 1 : 0.92，但海康相机的白平衡状态不明，这个偏差分不清来自灯还是来自相机。
- 一个 1440×1080、30 Hz 相机下实时因子 1.0（RTX 4060 Laptop）。

## 局限

- 录像是 2026 赛季场地，网格是 2027 版；表面按 CAD 材质归类后整体赋值，没有逐个零件对应。
- 场地的绝对照度（lux）没有算：需要镜头光圈和传感器的绝对响应标定。Gazebo 也用不到它。
- 能量机关在录像里是橙色（激活状态，随比赛进程变化），CAD 里是青色，保持 CAD。
- 灯条光晕、观众席大屏、灯光秀、裁判系统灯效都没有建模。
- D430 的深度和红外图像在 Gazebo 里与可见光照明无关；光照只影响 RGB 图像。
